### 修复
- **刘海 Mac 显示适配整体修复**（折叠态与刘海错位、展开态内容被摄像头模组遮挡）：
  - **展开态「贴顶+左右对称翼」布局，翼宽随内容自适应**：展开窗口（560pt）屏幕居中时刘海落在窗口正中，顶栏 tabs 与操作按钮直接流进刘海底下被物理遮挡。现按「窗口迁就内容」重排：前端实时测量顶栏内容（左翼 = logo + agent tabs 实宽，右翼 = token 计数器 + 5 个操作按钮实宽），经 `set_island_presentation` 新增的 `expanded_wing_left/right` 参数报给 Rust，Rust 取 **两翼对称值 = max(左翼需要, 右翼需要)**，展开窗口 = `刘海宽 + 2 × 翼` 且**严格屏幕居中**（各翼钳制 64–600pt，未测量前回退 300pt）——窗口中心恒在屏幕中心，展开/收起动画**零平移、纯对称生长**（两边缘等速向外），刘海列始终压在实体模组上；较宽一翼的富余是 tab 栏的生长余量（tabs 增多先填满本翼再触发加宽），agent tabs 超宽时在翼内滚动，`.more-menu` 下拉不再被任何 overflow 裁切；plan/settings（680pt）仍作为窗口下限
  - **展开翼测量三连修**（计数器遮挡 + 落定后第二段加宽同根因）：① 展开动画期间 chrome 未挂载，opening 阶段测量读到 ~0 并把展开打到过窄翼宽，落定后 chrome 挂载、计数器溢出翼下被遮挡——测量 effect 现仅于 expanded 阶段工作，展开目标直接使用上次实测翼宽；② `getBoundingClientRect` 会把 actions 集群的入场变换（scale 0.94→1）算进宽度导致测量偏小，改用 `offsetWidth`（布局宽度，与 transform 无关）；③ token 计数器以 `position: absolute; right: calc(100% + 5px)` 悬挂在操作簇盒外，测量此前完全没算它——现将其 `offsetWidth` + 5pt 间距计入右翼；④ 新增 ResizeObserver（计数器/操作簇/tab 栏）+ 落定事件复测，计数器走字变宽、tabs 增减时翼宽实时跟随，不再遮挡；翼宽持久化到 localStorage 并在启动时回种，重启后首次展开也是一步到位
  - **展开动画对称化**：刘海锚定展开的几何终点里左缘几乎不动（左翼内容 ≈ 折叠态左翼预算，实测左缘全程仅移动 ~2pt），旧插值让左缘把这点位移前置后长期静止，读起来像「只向右展开」。现把运动分解重排：宽度携带弹性缓动（大部分增长在前段）围绕窗口当前中心**对称向外爆发**，中心点改走对称 ease-in-out 滑向刘海锚位、尾段收敛——两边缘在整个动画里同步参与运动，终点仍精确落在刘海对齐位；收起方向镜像同理
  - **首次 agent logo 出现时折叠岛内容错位修复**：折叠态的呈现同步是「CSS 列宽即时生效、原生窗口 420ms 弹簧追赶」，dormant→compact 首次切换时 CSS 已切到三列网格（左翼 + 224pt 刘海列）而原生窗口还是 284pt 的 dormant 胶囊——网格溢出窗口、刘海列与实体模组错开 ~106pt，收尾才归位。现折叠**模式切换**（dormant ↔ compact ↔ micro）在刘海屏上改为 snap 同帧落地（CSS 与原生窗口同一帧变化，无错位窗口）；同模式的宽度微调保留平滑弹簧（瞬态偏移 ≤ 一个图标位）；非刘海屏无对齐约束、保留原有的平滑变形动画
  - **折叠胶囊两翼外边距加大**：刘海模式下翼内容与胶囊外缘几乎贴合（左翼 padding-left 为 0、右翼仅 8pt，宽度预算也只有 8pt）。新增 `COMPACT_NOTCH_OUTER_PADDING = 14`（刘海专用，无刘海保持 8pt 不变）：宽度预算（`computeCollapsedWindowWidth` / `computeCompactHeaderLayout` / `computeCompactLeftPaneWidth`）与 CSS 渲染（`--compact-outer-padding`）同源联动，窗口随外边距自动加宽、刘海对齐不受影响；顺带把 dormant 胶囊翼宽从 30pt 提到 42pt（`DORMANT_NOTCH_PADDING`），修掉 logo 尾部探进摄像头模组的几像素
  - **折叠胶囊宽度不再被 200pt 下限撑宽**：刘海宽度 = 辅助区间距 + 4pt 覆盖余量，旧逻辑对实测值也强制抬到 200pt 下限，窄刘海机型（如实测 112pt 间距被报告成 200pt）上黑色胶囊明显宽出实体刘海；200pt 现仅用于辅助区不可读的回退路径（新增 `NOTCH_WIDTH_SLOP` 常量，16" 实测机型 220→224pt 行为不变）
  - **形状脉冲不再破坏刘海对齐/顶出屏幕**：`pulse_island_shape` 旧逻辑横向居中扩展（刘海机上胶囊瞬间偏离摄像头模组）且纵向向上生长（顶边越出屏幕物理顶端进入不可见区，文件中转站吃/吐编排时肉眼可见）——锚点逻辑提取为纯函数 `pulse_target_position`：刘海+折叠态钉住左缘（右翼吸收宽度变化），顶边一律钉死，非刘海保持居中
  - **展开动画使用实时刘海数据**：`animate_island_window_mode` 旧逻辑在 home bounds 缺失时回退到"无刘海"默认值，展开窗口会少加 `extra_top` 摄像头模组补偿带导致内容被裁；现改用 AppState 中的实时刘海 metrics
  - **首帧水合竞态**：原生窗口在 setup 时已按刘海定型，但前端 CSS 变量要等 IPC 返回才就位，首帧会闪一帧未适配布局——`main.tsx` 现在先水合刘海 metrics 再 render（150ms 兜底防 IPC 异常拖住启动）
  - **显示器变化自愈**：新增 `NSApplicationDidChangeScreenParametersNotification` 监听（插拔显示器/改分辨率），刘海 metrics 变化即落库、广播 `notch-metrics-changed` 事件，前端刷新 CSS 变量并对折叠态 snap 重排（此前显示器变化后刘海参数一直过期到下次手动切换）
  - **NSScreen 匹配健壮化**：优先按显示器名（`localizedName`，与缩放系数无关）匹配、几何匹配作次选、窗口所在屏兜底；匹配失败不再静默降级为"无刘海"（那会让整个胶囊屏幕居中正好藏进刘海），现在会打 warning 日志，`ATOLL_DEBUG_NOTCH=1` 可输出候选屏与每次应用的窗口几何
- 新增 `scripts/calibrate_notch_metrics.py`：从截图量测本机摄像头模组的精确宽高与中心偏移（先退出 Atoll，在有录屏权限的终端运行），供上述常量按机型校准
