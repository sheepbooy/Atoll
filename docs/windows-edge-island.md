# Windows 贴边浮岛

Windows 的默认入口位于所选显示器工作区右侧约三分之一高度。折叠态高度为 32 个逻辑像素，显示 Atoll 吉祥物、在线状态及独立的审批、提醒徽标。点击展开，普通悬停不展开；拖入文件仍会快速展开。展开后保留原审批和会话面板，计数、音乐与歌词在展开面板查看。

在胶囊或展开态标题栏的空白处上下拖动，移动超过 6 个逻辑像素后视为拖拽；拖动后不触发点击展开。按钮和输入控件保留自身操作。右边缘始终固定，接近屏幕底部时展开面板会向上限位。

纵向位置按工作区高度比例存入 `~/.atoll/settings.json` 的 `windowsEdgePosition`，拖动过程中只更新内存，结束或取消拖动后保存。显示器切换、拔插、缩放和任务栏工作区变化会重新定位；所选显示器缺席时沿用主屏回落机制。展开时的临时限位不会修改折叠态保存位置。

Windows 隐藏原「小尺寸折叠浮岛」设置，原 `atoll.foldedIslandSize` 偏好保留但不用于 Windows 布局。通知设置不迁移：「强制打断」仍自动展开，「仅通知」保持折叠并更新徽标，点击通知、托盘或使用召回快捷键展开。托盘悬停不再召回。macOS 保持原顶栏布局和交互。

## 自动验证

- 前端回归测试：点击与悬停、旧偏好兼容、提醒双徽标、审批提醒模式、托盘召回、文件拖入，以及拖动阈值、取消、延迟与失败处理。
- Rust 几何测试：固定右边缘、负坐标屏幕、底部限位、小工作区、物理拖动与 100% / 125% / 150% / 200% 缩放的像素对齐。
- `npm run build`；`cargo test --manifest-path src-tauri/Cargo.toml --lib`。
- 当前 macOS 开发环境使用 Node 26，前端测试需 `NODE_OPTIONS=--no-experimental-webstorage npm test`，绕过该 Node 版本与 jsdom 的 Web Storage 冲突。
- Windows 交叉编译检查：`cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu --tests`。

当前检查结果：前端 63 个测试文件、567 个测试通过；Rust 397 个测试通过、6 个原有测试跳过；前端生产构建及 Windows 测试目标交叉编译通过。浏览器模拟 IPC 检查了折叠双徽标及展开歌词布局，无页面异常。

## Windows 实机验收（待执行）

浏览器中的模拟 IPC 可验证前端布局，不覆盖 HWND 区域、真实鼠标坐标或任务栏行为。当前开发主机为 macOS，以下项目需要在 Windows 上执行：

1. 点击胶囊展开、鼠标经过不展开；透明圆角外点击可到达下面应用，胶囊内点击可用。
2. 分别拖动折叠入口和展开标题栏：只能上下移动，松开不误点击，拖动期间不自动收起；重启后位置恢复。
3. 接近底部展开审批、计划及设置面板：完整位于工作区，收起回到保存位置；文件投喂形变右边缘无漂移。
4. 在不同缩放的双屏间切换，拔掉所选屏幕后回落主屏，再接回恢复；改变分辨率、任务栏位置及自动隐藏设置后仍可操作。
5. 先后验证「强制打断」与「仅通知」，以及通知点击、托盘点击、全局快捷键召回和再按收起。
6. 同时有审批和提醒时两个徽标均可见；文件拖入展开并成功投喂，音乐与歌词仅在展开态显示。
